# positions — 보유 포지션 등록·점검·정리 (P-8)

운영자의 실제 보유를 **계획(조건문)과 묶어 박제**하고, 매일 계획 대비 거리를 점검한다.
"왜 샀고 언제 나가기로 했는지"를 시스템이 기억하고 들이미는 게 목적.

## 경계 (절대금지 #2 정합)
- 손익·스탑 거리·시간손절 잔여 = **순수 코드**(`trading.position_check`). 자동 매매 없음.
- LLM(이 스킬)은 자유문 무효화 조건을 최신 이벤트·팩과 **대조 해설**만 — **정리 판단은 운영자**.

## 점검 (기본 — "/positions", "보유 점검")
1. `.env` 로드 후 `poetry run python -m trading.positions` 실행 — open 포지션별
   현재가(KIS 실시간→EOD 폴백)·손익%·스탑 잔여 거리·시간손절 잔여 거래일·[정리 검토] 플래그.
2. **무효화 대조(LLM)**: 각 포지션의 invalidation_text를 최신 검증 이벤트·거시와 대조해
   "무효화에 가까워졌는지" 해설(예: "이란 결렬 시 무효" → 오늘 이란 관련 confirmed 이벤트 확인).
   필요하면 해당 종목 DiscussPack(캐시)을 참조. 새 사실 없으면 결론을 바꾸지 않는다.
3. [정리 검토] 플래그(스탑 이탈·시간손절 도래)가 있으면 **맨 앞에서** 보고하고 정리 여부를
   운영자에게 묻는다. 정리 결정 시: `poetry run python -m trading.positions close <id> --reason "..."`.

## 등록 ("샀어", "포지션 등록")
1. 종목·수량·평단을 확인. **계획 스냅샷을 최대한 채운다** — 직전 discuss 토론이 있으면
   그 조건문(가설·트리거·무효화·스탑·시간손절·확신도)을 그대로 옮기고, 분석 문서 전문은
   임시 파일로 저장해 `--plan-file`로 박제. 없으면 운영자에게 스탑·시간손절만이라도 묻는다
   (출구 없는 포지션 등록은 경고).
2. `poetry run python -m trading.positions add --symbol <코드> --qty <수량> --price <평단>
   [--stop <가격>] [--time-stop <거래일>] [--confidence <0~1>] [--hypothesis "..."]
   [--invalidation "..."] [--plan-file <md>] [--source "discuss:<종목> v<N>"]`
3. 등록 후 점검 1회 실행해 현재 상태를 보여준다.

## 정리 ("팔았어", "정리")
- `close <pos-id> --reason "<사유>"` — 사유는 구체적으로(스탑 이탈/시간손절/무효화 관측/임의).
  임의 정리(계획 외)면 그 사실을 그대로 박제 — 나중에 R7이 준수율을 본다.

## 노출
- 아침: arm-check 산출에 "보유 포지션 점검" 섹션 자동 포함.
- 저녁: 21:00 보고 "보유 포지션 — 무효화 잔여 거리" 섹션 자동 포함.
- boot: 세션 시작 시 `poetry run python -m trading.positions`로 보유 현황 확인(있으면).

> 가드: 계산=코드/해설=LLM/판단=운영자 · 자동 매매·자동 정리 없음 · 등록은 운영자 명시 ·
> 무효화 대조는 검증 이벤트만(추측 금지) · 출구(스탑/시간손절) 없는 등록은 경고.
