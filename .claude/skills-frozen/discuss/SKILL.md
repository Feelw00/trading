# discuss — 종목 분석·토론

특정 종목을 **사전 조립된 컨텍스트 팩(DiscussPack)**으로 grounding해 추이·포지션을 **적대적으로** 토론한다.
예측기가 아니라 **조건문(무효화·트리거) 생성기**(설계서 §6 "조건문 공장 + 규율 집행기").

## 0. 입력
종목(이름/코드) + (선택) 운영자가 가져온 **소문/뉴스/의도**(진입·이탈 고려).

## 1. 컨텍스트 팩 — 캐시 확인 → (질문) → 조립 (P-5)
조립·캐시·신선도 판정은 전부 결정론 코드. LLM은 트리거·질문·토론만:
1. `.env` 로드 후 `poetry run python -m trading.discuss_pack <종목> --check`
   - **캐시 있음** → 출력(버전·built·FRESH/STALE)을 보여주고 **운영자에게 갱신 여부를 질문**한다.
     STALE(시세 DB보다 뒤짐)이면 갱신 권장을 명시. 재사용 선택 시 기본 모드로 팩 로드.
   - **캐시 없음** → 바로 build로.
   - 종목 못 찾으면(DB 미수집) `/collect` 제안.
2. (갱신 OK 또는 캐시 없음) `poetry run python -m trading.discuss_pack <종목> --build`
   - 내부에서 자동 보강: 뉴스 빈약 → 종목 쿼리 수집(COLLECT-4) / 수급 없음·구식 → KIS 종목별 1콜.
   - **뉴스 사실검증(가짜뉴스 필터)**: 기검증 이벤트(EventStore) 재사용 + **미평가 뉴스만**
     R2(이벤트화)→R4 **사실성 렌즈**(fabrication/sourcing/corroboration — 날조·출처·교차확인만
     공격, **중요도·신선도 판단 금지**). 결과는 confirmed/refuted/unverified + 렌즈 사유로 박제.
     일별 파이프라인의 촉매 가치 렌즈(`r4:claude`)와 `verified_by`로 구분된다.
   - 새 버전으로 캐시 저장(append-only) — 같은 종목 재토론 시 1번에서 재사용.
3. `poetry run python -m trading.discuss_pack <종목>` → 팩 JSON을 토론 grounding으로 사용.
4. **거시 백드롭:** 최신 `.runtime/collect/<날짜>/macro_indicators.sqlite` 읽기(있으면). 없으면 `collect-macro` 제안.

**팩 내용물**: 가격맥락+5일 변동률 · 공시·재무(DART) · 섹터/테마 · 뉴스(trust) ·
**수급 일별 5건+5/20일 누적(개인/외인/연기금/기관外)** · **검증된 이벤트(종목+소속 섹터)** · 결측 notes.
**모든 사실에 출처·as_of 표기.** 없는 데이터는 "미수집"(notes 그대로) — **지어내지 않는다**.

## 2. 운영자 입력 분리 + 근거 위계 (환각가드)
- 운영자가 가져온 소문/뉴스는 **`[UNVERIFIED]`** 로 명시 표기. 팩의 grounded 사실과 **절대 섞지 않는다.**
- **근거 위계(운영자 2026-06-11): 공시 원문(1차 사료) > 가격·수급(관측치) > R4 의견 > 뉴스 기사.**
- **R4 status는 의견이지 사실 판정이 아니다.** 적대검증은 기본 회의적 설계라 기각이 과대 산출된다
  (비판을 위한 비판 성향). `refuted`를 "사실 아님"으로 읽지 마라 — 반드시 `lenses`(생존비)와
  `lens_notes`(기각 사유)를 읽고, **기각 사유가 공시 원문·관측치와 충돌하면 상위 근거가 이긴다**
  (실례: 네이버 AI 팩토리 — R4는 묵은 기사 근거로 기각했지만 6/08 공시 원문이 신규 사실이었음).
  중요 이벤트는 공시 원문 대조(`document.xml`) 후 판단.

## 3. 적대적 분석 (반-아첨)
운영자 가설/소문을 **공격**한다(설계서 §6 표준 공격벡터):
- 신선도(팩 STALE?) · 교란변수 · 역사적 반례 · 수단-논제 정합성 · 컨센서스 할인(이미 가격에 반영?) · 타이밍-메커니즘 정합성.
- **수급 정합성**: 가설 방향과 5/20일 누적 포지션(외인·연기금·기관外)이 어긋나면 먼저 지적한다.
- **동조 금지 — 약점을 먼저 말한다.** 데이터가 가설과 어긋나면 그렇다고 말한다.
- **데이터 아티팩트 점검**: 액면병합/분할로 모멘텀 왜곡 여부(크레오에스지 1251% 사례 — 공시의 변경상장/거래정지해제 확인).

## 4. 포지션 프레이밍 (예측 아님)
산출은 전망이 아니라 조건문(`ThesisRecord` 형태):
- **가설**: 한 줄 + 방향(long/short/flat).
- **진입 트리거**: 구체 조건 — **지정가/조건부만**(시장가 금지, 절대금지 #3).
- **무효화(이탈)**: 관측가능한 조건(깨지면 논제 폐기) — **필수**. 없으면 토론 미완.
- **시계(horizon)**: 거래일(스윙 기본 3~15일).
- **확신도**: 0~1, 근거에 비례(과신 금지).
- **리스크/잔여매물**: 수급은 팩의 누적 포지션·일별 흐름으로 판단. 신용·공매도 잔고는 미수집 — "없음" 명시(추측 금지).

## 5. 토론 (인터랙티브)
- 운영자가 반박하면 grounded로 재응답. **새 사실 없이 결론 바꾸지 않는다.**
- 단정 금지: 확정 데이터로 확인이 필요한 지점(예: 장중 잠정 수급 — `/flows` 참조, 미확인 소문) 명시.

## 출력
grounded 브리핑(출처·as_of) → 적대적 분석(약점 먼저) → 조건문(가설/트리거/무효화/시계/확신도/리스크). 간결하게.

> **가드:** 수치 출처·as_of 필수 · 운영자 소문=`[UNVERIFIED]` 분리 · 시장가 금지 · 무효화 필수 · 반-아첨 · 미수집은 "없음"으로(추측 금지) · 캐시 갱신은 운영자 확인 후 · **R4 기각은 의견(공시·관측치가 상위)**.
