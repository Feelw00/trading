# arm-check — 아침 발동 판단 + 해설 + 분석

운영자가 9~10시 집행 직전, 어젯밤 승인한 OrderDraft가 **지금 발동 조건을 충족했는지**와
그 주문이 **무슨 뜻인지**를 한 번에 받는다(P-6). 예측이 아니라 **조건 충족 판정 + 번역**이다.

## 경계 (절대금지 #2 정합)
- **발동 판단(ACTIVE/INACTIVE)·흐름 수집·해설 = 순수 코드**(`trading.arm_check`). LLM은 판단하지 않는다.
- **LLM(이 스킬)은 4단계 분석만** — 코드가 끝낸 판단·관측치를 받아 리스크·맥락·집행 주의를 해설.
  새 발동 결정을 내리거나 관측치를 지어내지 않는다.

## 두 섹션 = 승인된 셋업 + 승인 후보 (아침에 검토·승인까지 한 곳에서)
승인은 저녁 CLI가 아니라 **아침 arm-check에서 통합** 처리한다(운영자 결정 2026-06-12). 산출은 둘:
- **승인된 셋업**(활성 풀): status=approved + TTL(time_stop_days 거래일) 미경과. 발동 여부 판단.
- **승인 후보**(미승인 draft): 어젯밤 R5가 낸 초안. "지금 승인하면 발동하나"를 미리 보여준다.

"어젯밤 승인했지만 오늘 미발동 → 모레 갭 오면 진입" 같은 다일 셋업을 놓치지 않는다(승인은 며칠 유효).
검토 후 의식적 승인이라는 마찰은 유지하되(설계서 §6), id 타이핑·저녁 CLI 강제는 없앤다.

## 흐름
1. `.env` 로드 후 `poetry run python -m trading.arm_check` 실행.
   - 내부: 활성 풀(approved) + 후보(draft) 로드 → 흐름 관측치 수집(KIS 실시간 체결강도·전고회복·
     호가불균형 + 주입 파일 `.runtime/flow/<날짜>.json`) → `selector.select()` 순수 판단 → 결정론 해설.
   - **KIS 미설정/장외면** 관측치가 비거나 stale일 수 있음 — 산출 머리말의 장중/장외 표기를 보라.
2. stdout 마크다운(승인된 셋업 + 승인 후보, 종목별 조건 O/X·트랜치·스탑·만료일)을 **grounding**으로 읽는다.
3. **승인 단계(통합)**: 승인 후보가 있으면 운영자에게 검토 정보(근거·발동 조건·"승인 시 발동" 미리보기)를
   제시하고 **어느 것을 승인할지 묻는다**(동조 금지 — 약점·미충족 먼저). 운영자가 지정한 것만
   `poetry run python -m trading.approve <id>` 로 승인. 자동 승인 금지.
4. 승인 후 그 셋업은 활성 풀에 들어간다 — 필요하면 arm_check를 한 번 더 돌려 갱신된 판단을 보여준다.
5. **4단계 LLM 분석**(아래)을 그 위에 얹어 운영자에게 보고.

## 4단계 분석 (반-아첨, grounded)
산출의 관측치·판단만 근거로:
- **미충족 조건의 의미**: 어떤 흐름변수가 왜 X인지(예: 체결강도 92 < 110 → 매수체결 미우세).
  관측치 없음(NXT 프리마켓 등)과 조건 미달을 **구분**한다.
- **평가 불가 조건 경고**: 시각(`09:30`)·문자열 등 selector가 평가 못 하는 조건은 "발동 판정에서
  빠졌음"을 명시(임의 보정 금지). boolean(`==true/==false`)·숫자 조건은 평가되므로 경고 대상 아님.
- **집행 주의**: 발동이라도 3트랜치는 70%가 플러시(하락 지정가 매집)·30%가 상승 확인임을 상기.
  "거래량 터지고 오르면 산다"가 아니라 **투매에 받고 회복에서 확인**하는 구조.
- **결측 정직**: premkt_volume_ratio 등 미수집은 "없음"으로(추측 금지).

## 보유 포지션 섹션 (P-8)
산출 하단에 "보유 포지션 점검"이 자동 포함된다(손익·스탑 잔여·시간손절 잔여·[정리 검토] 플래그).
[정리 검토]가 있으면 **신규 진입 검토보다 먼저** 보고하고, 무효화 자유문은 최신 검증 이벤트와
대조해 해설(판단은 운영자). 깊은 관리(등록·정리)는 `/positions`.

## 출력
[정리 검토] 포지션(있으면 맨 앞) → 승인된 셋업 요약(발동 N/전체) → 승인 후보(승인 시 발동
미리보기) → 승인 제안·질문 → 종목별 한 줄(발동/미충족 조건) → 집행 주의 → 결측. 간결하게.
**승인도 집행도 운영자가 결정** — arm-check는 판단·해설·승인 제안만 하고, 자동 승인·자동 주문은 없다.

> 가드: 발동 판단은 코드(LLM 미개입) · 승인은 운영자 확인 후 명시 id(자동 승인 금지) · 관측치 출처는 KIS 실시간/주입 파일(추측 금지) · 평가불가 조건 명시 · 시장가 금지 · 결측은 "없음" · 집행은 운영자 수동.
