# 2026-06-12 — R6 보고 가독성 2차 개편 (시나리오 구조화·결재 근거 배선·자동링크 차단)

운영자 피드백(6/11 저녁 보고): "일정한 규칙이 있는 것 같은데 인간이 읽기에 가독성이 너무
떨어진다" + "order.xxx.buy ID가 텔레그램에서 하이퍼링크로 걸린다".

## 원인 진단

1. **시나리오 통문단** — R5 출력 스키마가 `scenario_tree`를 자유 문자열 하나로 받았고,
   render의 사후 정규식 재구성(`분기 A)` / `[분기A]` 마커 기대)은 실제 산출(`축1(...): 분기 A-1:`)과
   미스매치로 한 번도 동작하지 않았음. 사후 재구성은 마커 변형에 깨진다 — 구조는 산출 시점에 강제해야.
2. **결재 근거 유실** — R5 프롬프트는 플레이북별 `"summary": "<저녁 결재 보고용 1줄>"`을
   생성시키는데 `_to_records`가 버림(Playbook 계약에 필드 부재). 결정 섹션이 코드·스탑만 나열.
3. **종목 코드만 표기** — 종목명 미병기. `0.5 * normal_unit` 내부 표현식 노출.
4. **R4 라인** — `(0.35)` 무라벨 숫자 + `_clip(80)` 문장 중간 절단.
5. **텔레그램 자동 링크** — `.buy`가 실제 gTLD라 ID가 URL로 오인됨(클라이언트 단 감지,
   평문인 한 차단 불가).

## 변경

- **`contracts/scenario.py` 신설** — `ScenarioAxis(title, lines)` + `axes_to_stored`/`axes_from_stored`
  (저장은 synth_runs.scenario_tree TEXT 재사용, JSON 배열). 레거시 산문은 줄 단위 무제목 축으로
  무손실 래핑(하위 호환).
- **R5** — 출력 스키마를 `[{title, lines[]}]`로 변경(+절대 규칙: 1줄 1분기, 통문단 금지),
  `R5Result.scenario_tree: list[ScenarioAxis]`, 문자열 불복종은 줄 단위 보존 폴백.
  `_to_records`가 `summary`를 Playbook에 보존(`Playbook.summary: str = ""` — 구레코드 호환 기본값).
- **PlaybookStore** — `append_run`/`latest_run`이 축 목록을 (역)직렬화.
- **render** — 깨진 정규식 재구성 삭제 → 축 제목 굵게 + 분기 불릿. 결정 섹션을
  "종목명(코드) 매수 — 근거 1줄 / 발동 조건·스탑·시간손절·상한·ID"로 자기완결화.
  종목명은 market.sqlite 폴백 조회(`_symbol_names`, 부재 시 코드). `_humanize_cap`
  ("0.5 * normal_unit"→"기본단위의 50%"). R4 라인 `(강도 X)` 라벨 + 문장 경계 절단(110자).
  모닝 보고에도 종목명·백틱 ID 적용.
- **tgfmt** — `` `코드` ``→`<code>` 변환 추가. 텔레그램은 엔티티 구간에 자동 링크를 적용하지
  않으므로 `.buy` gTLD 오인 링크 차단(부수 효과: 고정폭 표시).
