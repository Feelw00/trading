## 0. 운영 헌장

1. 우리는 예측하지 않고 **사이클의 위치를 측정**한다. 이미 오른 산업을 쫓지 않고, 관측 가능한
   실물 지표가 바닥권을 가리키는 곳에서 기다린다. 관측할 수 없는 사이클은 판정하지 않는다.
2. **사람도 LLM도 종목을 심사하지 않는다.** 종목의 편입·제외·비중·무효화는 검증 가능한 기계적
   규칙이 결정한다. 운영자는 규칙(정책)·자금 한도·거부권만 결정하며, 규칙의 수정은 포지션이
   아니라 분기 평가 루프(R7)를 통해서만 한다.
3. 개인의 유일한 구조적 엣지는 **시간**이다. 환매 압력이 없는 자본으로 기관이 기다릴 수 없는
   시간을 기다린다. 이 엣지는 중도 이탈 순간 소멸하므로, 청산은 가격이 아니라 **논제 붕괴**로만
   정당화된다. 가격 급락은 매도 신호가 아니라 논제 재점검 트리거다.

## 1. 목적·전제·설계 철학

이 시스템은 예측 기계가 아니라 **사이클 계측기 + 규칙 집행기**다. v0.2의 검증된 교훈(트리거
미충족 시 진입하지 않는 조건문 구조, 무효화 없는 분석 반려, append-only 근거 박제)은 유지하되,
엣지의 원천을 "장중 흐름의 쏠림"에서 **"산업 사이클의 저점과 자본의 인내"**로 옮긴다.

**운영 전제 (시스템 제약으로 강제):**

- 운영자는 엔지니어이며 트레이더가 아니다. 운영자의 검증된 능력은 종목 우열 판단이 아니라
  **파이프라인 감사**(룩어헤드 바이어스·stale 데이터·생존 편향·단위 오류 적발)다. 시스템은
  운영자에게 종목 판단을 요구하는 지점을 만들지 않는다.
- 투자 시계는 **년 단위**(논제당 6~36개월)다. 일 단위 가격 변동은 신호가 아니라 소음이며,
  시스템은 장중에 어떤 판단도 하지 않는다(집행조차 기계적 발주뿐).
- 운영자의 자기 진단(충동 매매 경향)은 v0.2와 동일하게 구조로 가둔다: 매수는 승인된 계획의
  분할 일정(DCA)로만, 임의 추가 매수·임의 청산 경로는 존재하지 않는다.
- 결측 지표는 운영자가 **수기 입력**할 수 있다(데이터 입력 경로 — 판단 아님). 수기 입력도
  `source="manual"`·`as_of` 필수.

세 가지 불변 원칙(개정): ① 숫자는 코드가 수집·계산하고 LLM은 수집 트리거(COLLECT-1 하네스)와
서술만 담당한다. ② 관측 불가능한 무효화 조건을 가진 논제는 스키마 검증에서 자동 반려한다.
③ 편입·제외·비중·무효화 판정에 재량(사람·LLM 공통)을 넣지 않는다 — 재량이 필요해 보이면
그것은 규칙의 결함이며, 규칙 개정(R7→운영자 승인)으로 해소한다.

## 2. 전체 아키텍처

```
[Collectors R0]─▶[Fact Store]─▶[게이트 R1]─▶[밸류에이션 R2]─▶[온도계 R3]─▶[스크리너 R4]─▶[포트폴리오 R5]─▶[보고 R6]
 (승인 어댑터)    (as_of+출처)    (코드)        (코드)           (코드)        (코드)          (코드)           │
                                                    └──▶[심사 패킷 R4.5 (LLM, 서술 전용)]──────┘              │
        [논제 가드 (일간 EOD, 코드)]──▶[알림 §8]                    [평가 R7 (분기, 코드+LLM 서술)] ◀──────────┘
```

### 판단·서술·수집의 분리 (모델 라우팅 개정)

| 작업 성격 | 주체 | 근거 |
|---|---|---|
| 밸류에이션·온도계·스크리너·포트폴리오·무효화 판정 | **순수 코드 (LLM 금지)** | 환각 차단 — v0.2에서 LLM이 앉던 판단석(R3~R5)을 전부 코드로 교체 |
| 수집(R0) | LLM 트리거 + 승인 어댑터 (COLLECT-1/3 유지) | 기확정 운영 결정 |
| 심사 패킷 서술(bull/bear case), 분기 평가 서술, 규칙 개정안 초안 | `claude -p` 서브프로세스 | 서술은 게이트가 아니다 — 감사 기록·운영자 참고자료이며 어떤 점수도 파이프라인에 주입되지 않는다 |

**LLM 프로바이더 확정(운영자 2026-08-27): 구독 2개, API 과금 0.** openclaw 서빙(트리거·수집
디스패치 에이전트 턴)=ChatGPT 구독 OAuth — 티어가 낮아도 light-context 트리거 전용이라 충분.
작업 LLM(R4.5·R7 서술)=`claude -p` 로컬 인증. **OpenAI API 키 경로는 폐기**(소비 코드 0곳 실측).
비용 구조: LLM 호출이 일 단위 배치에서 **월·분기 단위**로 줄어 비용은 v0.2 대비 1/10 이하 수렴.

## 3. 라운드 파이프라인

라운드 간 전달은 파일/DB 레코드로만 한다(프롬프트 체이닝 금지 유지). 리듬이 일 단위에서
**일(수집)·주(계측)·월(결재·집행)·분기(평가)** 4단으로 재편된다.

| 라운드 | 이름 | 엔진 | 리듬 (KST) | 핵심 출력 |
|---|---|---|---|---|
| R0 | 수집 | LLM+승인 어댑터 | 일간 EOD (18:00) | FactRecord |
| R1 | 신선도·정합성 게이트 | 코드 | 수집 직후 | 플래그 부착 FactRecord |
| R2 | 밸류에이션·환원 계산기 | 코드 | 주간 (토 09:00) | ValuationRecord |
| R3 | 산업 사이클 온도계 | 코드 | 주간 (토 09:30) | CycleRecord (섹터별) |
| R4 | 스크리너 (편입·제외 규칙) | 코드 | 주간 (토 10:00) | CandidateRecord + 탈락 사유 |
| R4.5 | 심사 패킷 서술 | claude -p | 신규 후보 발생 시 (월간 상한) | DossierRecord (bull/bear — 게이트 아님) |
| R5 | 포트폴리오·주문 초안 | 코드 | 월간 (첫 토요일) | PortfolioPlan, OrderDraft(DCA) |
| R6 | 보고 | 정적 렌더링 | 주간 다이제스트 (토 11:00) / 월간 결재 | 보고 2종 |
| R7 | 논제 이행 점검·규칙 개정 제안 | 코드 + LLM 서술 | 분기 | 이행 리포트, 규칙 개정안 |
| — | 논제 가드 | 코드 | 일간 EOD 체인 내 | 무효화 신호 → P0 |

### R0 — 수집
COLLECT-1(LLM 수집)·COLLECT-3(승인 어댑터만, 독자 웹서치 금지)·환각 가드 전부 유지. 축 재편:

- **존치**: 시세 EOD(data.go.kr), 수급(KIS flows — 창 60~120거래일로 확장), 거시(ECOS·FRED),
  공시(DART), 재무(fins), 섹터(KRX 업종). 뉴스는 축소 존치(논제 가드용 보유 종목 중대 공시·
  이벤트 한정 — 촉매 발굴용 광범위 수집 폐기).
- **신설(어댑터 확정분부터)**: 재무 심화·주주환원(PIVOT-3 — 자사주 취득·처분·소각, 배당,
  상장주식수), 사이클 실물 지표(PIVOT-2 — 수출입·재고/가동률·가격 스프레드; 소스 미확정 축은
  스텁+"관측치 없음", **단 운영자 수동 입력 채널(§4 규약)로 어댑터 확정 전에도 가동 가능**).
- **폐기**: 장중 실시간 계열(체결강도·호가·잠정 수급), NXT 프리마켓, 스윙 유니버스 확장분.

### R1 — 신선도·정합성 게이트 (v0.2 유지, 임계만 재조정)
신선도 단위를 리듬에 맞게 완화(시세·수급 T+1, 재무 분기+공시 시차, 실물 지표 월간). stale
입력으로 PortfolioPlan 생성 불가(하드 게이트 유지). 이중 소스 괴리 시 `conflict` 플래그 동일.

### R2 — 밸류에이션·환원 계산기 (코드)
게이트 통과 전 종목에 대해 결정론 산출:

- **개별**: PBR·PER·PSR·ROE(fins 자본·순이익·매출 × 시총), 부채비율·이자보상배율, FCF 근사,
  흑자 유지력(최근 N년 적자 횟수).
- **상대**: 소속 섹터(KRX 업종 — SECT-1) 중앙값 대비 percentile. **섹터 PBR 밴드**: 섹터 합산
  PBR의 장기 히스토리 대비 현재 percentile(자체 백필 — §10 Phase 1 선행 조건).
- **환원·거버넌스 (운영자 결정 2026-08-26: 당해·최근이 아니라 경향성)**: 단년 환원액은 사용
  금지 — 사이클 저점 기업의 정상적 배당 삭감을 역차별하지 않는다. 대신 **track record**로
  점수화: 최근 10년 배당 지급 연수·업사이클 환원 이력·소각 이벤트 횟수·환원 정책 공시의
  존재와 유지. **거버넌스 감점**: 물적분할 후 자회사 상장(분할상장) 이력, 소각 없는 자사주
  처분 이력 — 주주가치 훼손 전력은 공시로 관측 가능한 사실이다(PIVOT-3). **수위(④, 2026-08-26
  합의)**: 기본 = 최근 10년 내 이력 **감점(비중 축소)**, 반복 이력(2회+) = **탈락**. 영구 하드
  탈락은 지배구조 개편 이력이 있는 한국 대기업 다수를 걸러 유니버스를 과도하게 좁히므로
  배제. 시효·감점 폭은 정책 파라미터 — Phase 3 결재 때 실제 걸리는 종목 목록을 보고 확정.
- 결측은 결측으로 산출(`None` — 0이나 평균 대체 금지). 운영자 수기 백필 경로(`source="manual"`).

### R3 — 산업 사이클 온도계 (코드)
화이트리스트 산업(PIVOT-5 — 운영자 정책 승인 후 확정)별로 사이클 위치를 점수화.
**기준 축은 자체 과거 지표다(운영자 결정 2026-08-26)** — 외부 실물 지표 소스 확정을 기다리지
않고, 백필된 히스토리 대비 현재 위치(밴드 percentile)로 사이클을 판정한다:

- **1차 축(자체 히스토리 — 편입 판정의 기준)**: ① 섹터 합산 PBR 밴드 ② 섹터 영업이익률 밴드
  (마진 사이클 — 이익의 위치) ③ 섹터 합산 매출 증감 사이클. 전부 EOD 시세+재무 백필에서
  결정론 산출 — 외부 신규 소스 의존 없음.
- **금융 프로파일(운영자 결재 ⑧, 2026-08-28 — policy-v1.4)**: 매출액 계정이 구조적으로 없는
  업권(은행·증권)은 축을 대체한다 — ②′ ROE 밴드(Σ순이익/Σ자본) ③′ topline 사이클
  (순이자손익, 결측 시 영업이익 폴백). 판정 규칙은 동형이며 unknown 규율은 프로파일별 자기
  3축 완비 기준. 관측 창 실측: DART가 금융업 2022 이전 무자료 → 창 3년(매년 +1),
  topline z 성립 전까지 unknown 유지는 정직한 상태다.
- **보강 축(실물 지표 — 가점·조기 신호, 게이트 아님)**: 수주잔고·운임지수·가격 스프레드·
  수출입 등(PIVOT-2). 소스가 확정되는 산업부터 추가 — 미확정이어도 시스템은 가동된다.
- 각 축 percentile/z-score → 합성 온도(0~100)와 국면 라벨
  `bottoming|recovering|overheated|declining|unknown`. 1차 축이 결측인 섹터는 unknown(편입 불가).
- **bottoming 요건 = 낮음 + 개선 시작(② 보완, 2026-08-26 합의)**: 밴드 percentile은 위치만
  알려주고 반전을 알려주지 못한다("하단에서 3년 머무름" 가능). bottoming 판정은 밴드 하단
  **그리고** 마진·매출 축의 저점 대비 개선 모멘텀(정책 임계)을 함께 요구 — 하단이되 개선이
  없으면 declining 유지. 개선 모멘텀도 자체 히스토리에서 결정론 산출.
- **구조적 사양 필터(자체 데이터)**: 섹터 합산 매출의 장기(수년) 추세가 하향이면 밴드가 아무리
  낮아도 제외 — "역사적으로 싸다"와 "죽어간다"를 매출 추세로 구분한다. 운영자 제외 목록
  (정책)이 이를 보완(자동 추론 금지).
- **밴드 무결성 가드(② 보완)**: ⓐ 백필의 **생존 편향**(상폐 종목 누락 = 낙관 왜곡) — 가능하면
  KRX 업종지수 등 지수 레벨 데이터로 교차검증하고, 불가 구간은 밴드에 한계 표기.
  ⓑ **구성 변화**: 섹터 구성 종목 수·합산 시총이 급변(재분류·대형 신규 상장)하면 플래그 —
  밴드 연속성이 깨진 섹터는 해당 구간 percentile을 신뢰하지 않는다.
- **한계 명시**: 히스토리 밴드는 상대 판정이다 — 시장 전체가 고평가면 밴드 하단도 절대적으로
  비쌀 수 있다. 거시 축(ECOS·FRED)을 온도 보정이 아니라 보고 병기로만 사용(판정 오염 금지).

### R4 — 스크리너 (코드 — 편입·제외는 여기서만 결정된다)

> **P-18 개정(운영자 결재 2026-08-31) — 우선순위 반전: "핵심은 가치투자, 사이클은 도구".**
> 발동 존(bottoming|recovering ∧ 화이트리스트)은 **게이트에서 폐지**되고 도구로 강등된다.
> 심사 유니버스는 화이트리스트가 아니라 **전 상장 재무 확보 종목**(결재 ②). 아래 원문의
> "발동 존" 문단은 역사 기록으로 보존하며, 현행 규칙은 이 블록이 우선한다:
> - **게이트(탈락 결정)는 가치·건전성만**: ① 가치 병행(결재 ③ — 산업 내 PBR 하위 40%
>   **또는** 시장 전체 하위 40%, 둘 다 박제) ② 생존력(적자·부채, 금융업 면제)
>   ③ 가치 함정 방어(ROE — v1.2) ④ 구조적 사양 가드 ⑤ 하드 탈락(PBR 산출 불가).
> - **사이클(R3)은 도구 3역할**: 우선순위·사이징(바닥·회복 산업 우대 — R5 §6 결재와 연계) ·
>   과열 경고 플래그(결재 ① — `cycle_caution`, 탈락 아님) · 화이트리스트는 "사이클 계측
>   신뢰도 라벨"로 격하(편입 우주 아님).

(v0.3 원문 — P-18로 대체됨) 발동 존: R3 국면이 `bottoming|recovering`인 화이트리스트 섹터.
그 안에서:

1. **가치**: 섹터 내 PBR 하위 percentile(정책 파라미터).
2. **생존력**: 흑자 유지력·부채비율·이자보상배율 임계 — 밸류 트랩 1차 방어.
3. **탈락 필터(하드)**: 연속 적자 N년, 자본잠식, 감사의견 비적정, 관리종목·거래정지.
4. **환원 가점**: R2 환원 점수.
5. **수급 네거티브 스크린**(PIVOT-4): 60~120거래일 기관+외인 **동반 지속 순매도**면 경고 플래그
   (편입 차단이 아니라 감점+패킷 명시 — 강등된 역할. 선정 가점으로는 사용 금지).

출력은 후보와 **탈락 사유 전수 박제**(어느 규칙이 걸렀는지 — R7 규칙 감사의 원료).

### R4.5 — 심사 패킷 서술 (claude -p — 게이트 아님)
신규 후보에 한해 bull case·**bear case(의무)**·산업 사이클 서술·리스크 요인을 조립한
DossierRecord 생성. **어떤 수치·점수도 산출하지 않으며 파이프라인의 어떤 판정에도 입력되지
않는다** — 월간 결재 보고에 첨부되는 감사 기록이자 운영자 veto 판단 참고자료다. 사실 주장은
FactRecord id 귀속 필수(환각 가드), 귀속 불가 주장은 렌더링에서 UNVERIFIED 표기.

### R5 — 포트폴리오·주문 초안 (코드)
승인 규칙(정책 파라미터: 종목당 비중 상한·섹터당 상한·현금 버퍼·후보 수 상한)에 따라:

- 목표 포트폴리오 산출 → 현재 보유와 diff → **DCA 계획**: 종목당 목표 금액을 N개월(정책,
  기본 3~6개월) 분할, 월 1회 지정가 발주 일정 생성.
- OrderDraft는 지정가 전용(절대금지 #3 유지). 지정가 산정은 결정론(직전 종가 기준 밴드).
- 청산 초안: 논제 붕괴 판정분(논제 가드)·목표 국면 도달분(R3 `overheated`)의 분할 매도 일정.
- 유휴 현금: P-12(코어 지수 ETF 대기소) 규칙 통합 — 정책 파라미터로 활성화(운영자 결정).

### R6 — 보고
- **주간 다이제스트(토, 읽기 전용)**: 온도계 변화, 후보 진입/탈락(사유 포함), 보유 논제 이행
  상태, 수급 경고. 대부분의 주의 결론은 "변화 없음"이어야 정상.
- **월간 결재 보고(의사결정 문서)**: 신규 편입·청산 초안 + 심사 패킷 첨부 + **veto 창(다음 집행
  슬롯 전까지)**. 운영자의 정기 판단 시점은 월 1회뿐이다.

### R7 — 논제 이행 점검·규칙 개정 제안 (분기)
- **논제 이행 채점(코드)**: 각 보유 논제의 사이클 지표가 편입 시점 예상 경로(회복 지속) 위에
  있는가 — 가격이 아니라 **지표로 채점**한다. 이행 이탈 N분기 연속 = 논제 붕괴 후보.
- **규칙 감사(코드)**: 탈락 사유 분포, 필터별 통과율, 밸류 트랩 적중(탈락 후 실제 부실화)
  추적 — 규칙이 의도대로 동작하는지의 계측.
- **규칙 개정안(LLM 서술 → 운영자 승인)**: 자동 적용 금지, 버전 태깅 유지(v0.2 동일).
- 사후 검증 리플레이: 과거 확정 사이클에 현행 규칙을 소급 적용해 편입/탈락을 관찰 — 표본
  부족한 정량 백테스트의 보완재. **튜닝용과 검증용 사이클을 분리**한다(예: 튜닝=반도체 2016·
  화학 2015 / 검증=해운 2020·은행 2020) — 임계를 고정한 뒤 검증 사이클에 1회만 적용하고,
  실패로 임계를 고치면 검증 사이클은 재사용 금지(오버피팅을 검증이라 부르지 않는다).

### 논제 가드 (일간, 코드 — v0.2 이벤트 감시기의 계승)
일간 EOD 체인에서 보유 종목만 검사. 장중 상주 프로세스는 없다.

- 무효화 조건 충족(재무 훼손 공시·환원 철회·감사의견 등 **관측 가능 이벤트**) → P0 → 청산 경로.
- **급락 = 긴급 재심사 트리거(운영자 결정 2026-08-26 — 손절 트리거 아님)**: 편입 평단 대비
  낙폭 임계(정책 파라미터, 제안 기본 -25%) 또는 섹터 대비 초과 하락 도달 시, 매도가 아니라
  **R4 스크리너 즉시 재통과 검사 + 공시 전수 스캔**을 발동. 탈락=무효화 경로(P0→veto 창→분할
  청산). 재통과는 두 갈래(① 보완, 2026-08-26 합의):
  - **원인 규명됨**(급락이 공시·관측 이벤트에 귀속) → 보유 지속, DCA 일정 불변.
  - **원인 불명**(귀속 가능한 공시·이벤트 부재) → 보유는 유지하되 **DCA 잔여 트랜치 일시정지**
    (매수만 중단) — 재심사가 후행 재무를 보고 통과를 남발하는 사각지대 방어. "시장이 아는 것을
    우리가 모르는" 상태에서 추가 매수 금지. 다음 분기 재무 반영 재심사 통과 시 재개.
  좋은 기업의 급락은 장기적으로 회복되는 경우가 많으므로 가격 자체는 어떤 매도 판정에도
  입력되지 않는다 — 재심사의 스케줄러일 뿐이다. 동일 종목 재발동 쿨다운(재심사 통과 후 추가
  -10%p 하락 시에만 재발동)으로 반복 소음 차단.

**저장소 (운영자 결정 2026-08-26, PIVOT-8 — v0.2 문서의 PostgreSQL을 실구현 현실로 공식화):**
**SQLite 도메인별 파일**(`data/*.sqlite`, WAL 모드), append-only(UPDATE/DELETE 금지 — 앱 계층
규율로 강제). journal 계층·fins·flows가 이미 이 패턴 — PostgreSQL/docker 의존은 Phase 0에서
제거. `data/`는 git 제외 유지, 백업은 주기적 파일 복사(운영 절차).

**DB-first 원칙:** 라운드는 DB만 읽는다 — 수집기는 갭만 채운다(증분). 한 번 적재된 데이터는
재수집하지 않으며(멱등), 히스토리 백필은 1회 적재 후 영구 재사용.

**운영자 수동 입력 규약(정식 소스 채널 — PIVOT-8):** API가 없거나 어려운 사실 데이터(실물
지표 등)는 운영자가 입력할 수 있다. 가드: ① `source="manual:<출처명>"`·`as_of` 필수
② 단위·범위 검증 + 전회 대비 급변 시 재확인 요구(오타 방어) ③ 수정은 새 버전 레코드
④ 신선도 게이트 동일 적용(낡은 수기 입력=stale) ⑤ 자동 어댑터 확정 시 manual보다 우선
⑥ **입력 가능한 것은 사실(지표값)뿐** — 점수·국면·판단의 입력 경로는 존재하지 않는다.

휴면"은 "장중 시스템 휴면"으로 강화된다(집행 슬롯의 기계적 발주만 예외).

## 6. 집행·규율 레이어 — DCA와 논제 기반 청산

v0.2 §6의 "청산 우선 자동화"(브래킷·시간손절)는 스윙 전제였으므로 폐기하고, 장투 규율로 교체:

- **진입 = 승인된 DCA 일정뿐.** 월 슬롯에서 계획된 트랜치만 지정가 발주. 가격이 내렸다고
  일정 외 추가 매수 없음(물타기 충동의 구조적 차단 — 다음 트랜치가 어차피 더 싸게 산다).
  미체결분은 다음 슬롯 이월(지정가 재산정, 결정론).
- **가격 손절 없음.** 저PBR 매수 후 하락은 전제된 시나리오다. 대신 **논제 붕괴 = 유일한 강제
  청산 사유**: 논제 가드·R7이 무효화 조건 충족을 판정(코드) → P0 → veto 창(2거래일) → 분할
  매도 개시. 목표 국면 도달(R3 `overheated`)도 동일 경로의 분할 청산.
- **비중 상한(정책 파라미터, 운영자 승인)**: 종목당·섹터당 상한, 현금 버퍼 하한. 집중 리스크는
  손절이 아니라 상한으로 관리한다.
- **자금 규모 무차별(운영자 결정 2026-08-26)**: 계좌 규모·유동자금으로 편입 종목 수나 전략을
  분기하지 않는다(v0.2 저잔고 모드류 부활 금지 — 자금 변수로 분류하면 더 꼬인다). 배분은 목표
  비중 그대로, 트랜치가 1주 미만이면 **다음 슬롯으로 병합 이월**(기계적 처리 — 정책 분기 아님).
  **1주 가격이 종목당 비중 상한을 초과하는 종목은 편입 불가**(③ — 자연 제약이지 정책 분기가
  아니다). 소액 구간에서 포트폴리오가 3~5종목으로 수렴하는 결과를 수용한다.
- 시장가 주문 금지(절대금지 #3)·지정가 전용 어댑터·킬 스위치는 유지. 브로커 어댑터(toss.py)는
  존치하되 조건부 주문(OCO/SINGLE) 경로는 사용 중단.
- **집행 브로커는 토스 단일(운영자 2026-08-27, PIVOT-9)** — KIS는 수급 조회 전용으로 실투자
  미사용, 주문·계좌 경로 영구 배제.
- 장중에 떠오른 아이디어: v0.2와 동일 — 저널 기록만, 다음 주간 사이클의 입력으로만.

## 7. 평가 루프 — §3 R7 참조
채점 대상이 "예측 적중"에서 "규칙의 건전성과 논제 이행"으로 바뀐다. 수익률은 후행 참고
지표이고, 선행 KPI는 규칙 준수율(일정 외 매매 0건)·데이터 커버리지·논제 이행률이다.

## 8. 알림·보고 체계

원칙 유지: 모든 알림은 사전 정의된 행동에 매핑, 4요소 페이로드. 장중 알림은 소멸한다.

| 등급 | 채널 | 조건 | 매핑 행동 |
|---|---|---|---|
| P0 | Telegram 즉시 | 논제 붕괴 판정, 급락 재심사 탈락, 보유 종목 중대 공시(감사의견·자본잠식·환원 철회), 집행 오류 | veto 창 내 확인 (기본값: 규칙대로 진행) |
| P1 | 주간 다이제스트 | 온도계 국면 전환, 후보 진입/탈락, 수급 경고, 데이터 결측 | 주말 검토 |
| P2 | 보고서 포함만 | 그 외 전부 | 없음 |

**침묵=진행의 전제는 전달 확인이다(7/14 사고 교훈):** P0 발송 실패·채널(게이트웨이) 다운이
감지되면 veto 창 카운트다운을 시작하지 않고 해당 집행을 보류+재시도한다 — 알림이 전달됐다는
보장 없이 시스템이 운영자의 침묵을 승인으로 해석할 자격은 없다.

## 9. 운영·장애 대응
v0.2 유지(신선도 게이트가 수집기 파손 감지, 스키마 위반 재시도 후 폐기, as_of 없는 숫자 출력
금지). 리듬이 느려 장애 복구 여유가 크다 — 주간 체인 실패는 차주 재실행으로 자연 흡수, 월간
결재만 P1 재실행 알림.

## 10. 로드맵

**Phase 0 — 복구·대사·동결 (즉시).** bootstrap 환경 복구(**PostgreSQL/docker 의존 제거 —
스택은 SQLite, PIVOT-8**) → 브로커 실측 대사(PIVOT-6: 보유 피에스케이·S-Oil, 잔존 조건주문)
→ 기존 조건주문 정리 → v0.2 cron 미등록 상태 유지(동결). 기존 포지션은 Phase 3 규칙 가동 후
재심사.

**Phase 1 — 밸류에이션·히스토리 기반 (3~4주).** **장기 백필이 이 Phase의 본체다**(온도계
1차 축의 선행 조건 — 운영자 결정으로 사이클 판정 기준이 자체 과거 지표이므로): DART 연도별
재무 소급 + 상장주식수×과거 종가로 섹터 PBR·마진·매출 히스토리 구축(목표 10년, 가용 범위
정직 표기). fins 확장, R2 계산기, 환원·거버넌스 경향성 수집(PIVOT-3 — 분할상장·자사주 처분
이력 포함, API 확정분부터·미확정은 스텁). AC: 전 종목 ValuationRecord + 섹터 3축 히스토리
밴드 산출 + 결측 정직 표기 + 계산 검증(공시 실측 대조 N종목).

**Phase 2 — 온도계·화이트리스트 (2~3주).** R3 v1을 **자체 히스토리 3축**으로 가동. 화이트리스트
후보 큐레이션(산업 특성: 설비투자 리드타임·commodity·글로벌 수요 연동) + 산업별 실물 보강 축
매핑표 작성 → **운영자 정책 결재(PIVOT-5)**. 실물 지표 어댑터(PIVOT-2)는 소스 확정분부터
보강 축으로 추가(게이트 아님 — 미확정이어도 가동). AC: 화이트리스트 전 산업 CycleRecord(1차
축 완비·secular_decline 판정 포함) + **튜닝용 과거 사이클 재현**(반도체 2016이 bottoming으로
찍히는가 — 검증용 사이클은 Phase 3에서 임계 고정 후 1회).

**Phase 3 — 스크리너·보고 리듬 (2주 + 관찰 1~2개월).** R4·R4.5·R5·R6 가동 — **집행 없는 페이퍼
모드**. 주간·월간 리듬을 실제로 돌리며 후보 품질·규칙 탈락 분포 관찰, 기존 보유 2종 재심사.
AC: 월간 결재 보고 2회 발행 + 운영자 규칙(정책 파라미터) 승인 완료.

**Phase 4 — 집행 (조건부).** DCA 지정가 발주 자동화(소액, 월 슬롯). 전제: Phase 3 관찰에서
규칙 개정 소요가 수렴 + 브로커 발주 경로 실측 확정. 이후 분기 R7 첫 사이클로 폐루프 완성.
